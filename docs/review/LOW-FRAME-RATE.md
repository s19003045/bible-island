# 低幀率的移動時間修正

2026-11-17。補驗正式希律長路線時，觀察到低幀率下行走非常慢；來源world.js把每幀elapsed封頂0.05秒，低於20FPS便丟失可見時間。這是確定的時間處理問題，並不等於已定位全部GPU／瀏覽器效能原因。

frame-time.js改為可見幀最多補算0.25秒，分成不大於1/60秒的步驟。每小步按原順序更新各NPC與主角，保留POI各自seed、狀態timer、容量、分離、社交機率及碰撞。這是物理時間分割，沒有新增群體決策timer或同步NPC狀態。渲染仍每幀一次；暫停保留NPC時鐘，隱藏／modal期間仍丟棄elapsed；長停頓不無上限追趕。

實際希律場景、NPC及walk-controls整合測試在4／10／60FPS各走20秒擁擠上階梯路段，檢查距離接近、著地、爬梯狀態及每步社交間距；十秒停頓後單幀位移少於0.5m。首輪只有dt上限改0.25，4FPS仍因路徑節點逐幀消耗不完時間而落後約2.5m；加入小步分割後通過。沒有以放寬測試掩蓋差異。

這項修正不保證4FPS本身看起來流暢，也不修復低於4FPS的所有慢速；0.25秒上限仍會丟棄更長幀時間。正式IAB曾有CDP／截圖逾時與右側裁切，不能把這些環境現象當作實體手機效能已驗。全來源回歸、發布與實際操作結果接續記錄於DEPLOYMENTS與逐島文件。

修正後完整來源回歸51檔319項通過（198.78秒）；check、diff與220323KiB離線包通過。既有素材／錄音未變，不重做Blender或生成任何配音。
